# เว็บไซต์งานเภสัชสนเทศ (DIS Site)

เว็บสถิตย์ (static site) ล้วน — HTML/CSS/JS ธรรมดา ไม่มี build step ไม่มี backend
แก้ไฟล์แล้ว push ขึ้น GitHub ก็ขึ้นเว็บจริงทันทีผ่าน GitHub Pages ฟรี

## เนื้อหาไหนลงเว็บได้ เนื้อหาไหนต้องขึ้น Drive แทน (สำคัญ)

Repo นี้เป็น **public เต็มรูปแบบ** (เงื่อนไขของ GitHub Pages ฟรี) ใครก็เข้าดู/ดาวน์โหลดได้โดยไม่ต้องล็อกอิน
เว็บนี้ไม่มี ระบบ user/login จริง (ตัดสินใจแล้วว่าไม่คุ้มสร้างเองสำหรับ static site ขนาดนี้)

**กฎการตัดสินใจ:**
- เนื้อหาที่หมอ/พยาบาล/คนนอกกลุ่มงานเภสัชกรรมเห็นได้ไม่มีปัญหา (ข่าว, คู่มือทั่วไป, ลิงก์ฐานข้อมูลสาธารณะ, โปสเตอร์ประชาสัมพันธ์) → อัปโหลดเข้า repo นี้ตรงๆ ได้เลย
- เนื้อหาที่อยากจำกัดเฉพาะกลุ่มงานเภสัชกรรม (ข้อมูลสต็อกยาจริง, ระเบียบภายในที่ละเอียดอ่อน, ข้อมูลที่ไม่อยากให้คนนอกเห็น) → **อัปโหลดขึ้น Google Drive แชร์เฉพาะกลุ่มงาน (จำกัดสิทธิ์ตาม Google account)** แล้วเว็บนี้ใส่แค่ "ลิงก์เข้าระบบภายใน" ชี้ไปหา ไม่เอาไฟล์/ข้อมูลจริงมาลงเว็บ
  - ตัวอย่างที่ทำแล้ว: [dashboard-covid.html](dashboard-covid.html) ไม่ฝังข้อมูลสต็อกยาลงหน้าเว็บ มีแค่ลิงก์ออกไปหาระบบ Apps Script ที่ deploy แยกไว้
  - รหัสผ่าน/ช่องกรอกบนเว็บ (ถ้ามี) เป็นแค่ตัวกันคนทั่วไปเดินผ่านมาเจอ **ไม่ใช่ความปลอดภัยจริง** ของจริงต้องพึ่งสิทธิ์ Google Drive/Workspace

## โครงสร้างไฟล์

```
dis-site/
├── index.html          หน้าแรก + ข่าว
├── css/theme.css        สีธีม (CI กทม.: เขียว #00744B + ทอง) แก้ที่นี่ที่เดียว
├── js/partials.js       เมนู/ฟุตเตอร์ที่ใช้ร่วมทุกหน้า
├── js/main.js           โหลดข่าวจาก data/news.json มาแสดง
└── data/news.json       รายการข่าว — เพิ่มข่าวใหม่แก้ไฟล์นี้อย่างเดียว
```

## วิธีเพิ่มข่าว (Newsletter)

ข่าวทุกชิ้นอยู่ใน `data/news.json` — หน้าแรกโชว์ 6 ชิ้นล่าสุดแบบย่อ, หน้า `news.html` โชว์ทั้งหมดแบบเต็ม + ตัวกรองหมวด
ไม่ลง PDF ต้นฉบับบนเว็บ (มีตราประทับ/ลายเซ็น) — ระบุแค่เลขที่หนังสือ + ลงวันที่ใน `ref` ก็พอ

```json
{
  "id": "2569-09-บริษัท-ยา",        // ไม่ซ้ำกัน ใช้เป็น anchor (news.html#id)
  "issue": "2569-09",               // งวดข่าว (ปี-เดือน พ.ศ.)
  "date": "2026-09-01",             // วันที่ในหนังสือ (ค.ศ. ISO) ใช้เรียงลำดับ
  "tag": "ยกเลิกจำหน่าย",           // ดูหมวดด้านล่าง
  "company": "ชื่อบริษัท",
  "title": "หัวข้อข่าว 1 บรรทัด — ระบุยา/ความแรง/ขนาดบรรจุตามหนังสือ",
  "summary": "สรุป 1-2 ประโยค: อะไร เมื่อไร กระทบยังไง",
  "points": ["ข้อเท็จจริงจากหนังสือ ทีละข้อ ห้ามเติมสิ่งที่หนังสือไม่ได้บอก"],
  "ref": "หนังสือ ... ที่ ... ลงวันที่ ...",
  "link": ""                        // ลิงก์ภายนอก (ถ้ามี) จะขึ้นปุ่ม "อ่านเพิ่มเติม"
}
```

**หมวด (`tag`) และสี** — กำหนดใน `TAG_STYLE` ของ `js/main.js`: `ยกเลิกจำหน่าย` (แดง) · `ยาขาดคราว` (ส้ม) · `เปลี่ยนแปลงผลิตภัณฑ์` (ฟ้า) · `ราคา` (ทอง) · `ตัวแทนจำหน่าย` (ม่วง) · `ประกาศ` (ทอง) · `ข่าว` (เขียว)

**กฎการสรุป** — หนังสือแจ้งเป็นเอกสารทางการ สรุปผิดไม่ได้: ตัวเลข/วันที่/Lot/รหัส ต้องซูมดูจากสแกนให้ชัดก่อนใส่ (เครื่องที่ไม่มี Poppler ใช้ Windows PDF API ผ่าน PowerShell render เป็น PNG ได้), ไม่เติมชื่อสามัญ/ข้อมูลที่หนังสือไม่ได้ระบุ. เว็บมีไว้ "แจ้งเพื่อทราบ" เท่านั้น ไม่ใส่ข้อเสนอแนะ/สิ่งที่ควรทำ/หมายเหตุ (แจ้งในกลุ่ม LINE แทน)

## วิธีดูตัวอย่างก่อน publish

เปิด `index.html` ตรงๆ ผ่าน double-click **จะโหลดข่าวไม่ได้** เพราะเบราว์เซอร์บล็อก fetch บน `file://`
ให้รัน local server แทน (เลือกอย่างใดอย่างหนึ่ง):

```bash
# ถ้ามี Python
python -m http.server 8000
```

แล้วเปิด `http://localhost:8000` — หรือใช้ preview ผ่าน Claude Code ก็ได้เลย

## วิธีขึ้นเว็บจริงด้วย GitHub Pages (ฟรี)

1. สร้าง repo ใหม่บน GitHub (public หรือ private ก็ได้ — Pages ใช้ได้ทั้งคู่ถ้า public, private ต้องมี GitHub Pro)
2. push โฟลเดอร์นี้ทั้งหมดขึ้น repo (branch `main`)
3. ไปที่ repo → **Settings → Pages**
4. ตั้ง **Source: Deploy from a branch**, เลือก branch `main`, folder `/(root)`
5. รอ 1-2 นาที เว็บจะขึ้นที่ `https://<username>.github.io/<repo-name>/`

ถ้าอยากผูกโดเมนของ รพ. เองในอนาคต ตั้งค่าเพิ่มได้ที่ Settings → Pages → Custom domain ทีหลังได้เลย ไม่ต้องแก้โค้ด

## ขยายเพิ่มหน้าใหม่ (Policy, ทะเบียนยา, Database links, ฯลฯ)

1. สร้างไฟล์ `.html` ใหม่ในโฟลเดอร์นี้ (เช่น `sop.html`)
2. copy โครง `<header>`/`<footer>`/script tags จาก `index.html` — **อย่าลืม copy query string `?v=N` ท้าย `theme.css`/`partials.js`/`main.js` ไปด้วย** (ดูหัวข้อ cache ด้านล่าง)
3. ตั้ง `data-active="sop"` ใน `<header id="site-header">` ให้ตรงกับ `key` ใน `js/partials.js` (ถ้าอยู่ใน dropdown ก็ใช้ key ของลูก ไม่ใช่ key ของกลุ่ม)
4. ไปแก้ `js/partials.js` เอา `soon: true` ของเมนูนั้นออก แล้วเว็บทุกหน้าจะลิงก์ไปหาได้ทันที — ธีมสี/ฟอนต์เหมือนหน้าแรกอัตโนมัติเพราะใช้ `css/theme.css` ร่วมกัน

## แก้ CSS/JS แล้วผู้ใช้เห็นของเก่าค้าง (browser cache)

`theme.css`, `js/partials.js`, `js/main.js` ถูกลิงก์ด้วย query string `?v=2` ท้ายชื่อไฟล์ (เช่น `css/theme.css?v=2`)
**ทุกครั้งที่แก้ไฟล์พวกนี้ ต้องเพิ่มเลข v ในทุกหน้าที่ลิงก์ไฟล์นั้น** (เช่น `?v=2` → `?v=3`) ไม่งั้นเบราว์เซอร์ของคนที่เคยเข้าเว็บแล้วจะยังใช้ไฟล์เวอร์ชันเก่าจากแคชอยู่ ทำให้เห็นบั๊กที่แก้ไปแล้วเหมือนไม่หาย (สาเหตุที่ dropdown เมนูเคยดูเหมือนค้างโชว์ตลอดเวลา)
